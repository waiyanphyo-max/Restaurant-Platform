## Acceptance boundaries

- M1 web auth supports email/password, session restore/refresh and email invitation acceptance. Phone/SMS OTP, same-UUID verified phone linking, and authorized phone invitation claim are not implemented.
- Identity derives from validated JWT sub, memberships and backend permission. Never trust client role/user/restaurant fields or unverified email/phone matches.
- Common QR and Table QR stay public; no account is required. Public API calls omit bearer auth. QR and queue tokens are scoped credentials, not user identity.
- Current delivery assignment requires DELIVERY_DRIVER. Target Owner/Manager assignment includes any eligible active member/self; Staff and Driver task access is assigned-only.
- “Complete” requires API authorization, loading/empty/error states and suitable tests, not just a component.
- Test statuses above were source-inspected. Previous M2 verification is reported as recorded, not rerun for this documentation audit. No live Supabase SMS/email, Android device, or production deployment test is certified.
