# Restaurant Platform: Spring Boot JPA Entities + Repositories

This project contains entity/repository mappings for all 24 tables in the submitted Supabase/PostgreSQL schema.

## Packages
- `com.restaurant.platform.entity`: JPA entity classes and the composite key class.
- `com.restaurant.platform.repository`: Spring Data JPA repositories.

## Important modelling notes
1. Foreign keys are represented as `UUID` properties rather than Java object relationships. PostgreSQL still enforces the foreign keys, composite foreign keys, unique constraints, and checks from your SQL schema. This avoids incorrect `@ManyToOne` join mapping for the repeated `restaurant_id` columns and composite constraints. You can add explicit entity associations later where useful.
2. `ProductModifierGroup` uses the composite primary key `(product_id, modifier_group_id)` via `ProductModifierGroupId`.
3. `RestaurantSettings.restaurantId` is its primary key. `Profile.id` is supplied by Supabase Auth (`auth.users.id`), so it is not generated by JPA.
4. Currency values and fees use `Long` for PostgreSQL `BIGINT`; geographic coordinates use `BigDecimal`; `TIMESTAMPTZ` fields use `OffsetDateTime`; queue dates use `LocalDate`.
5. Status/role fields are `String` and are constrained in PostgreSQL. This makes the Java mapping match the schema exactly; the service layer should validate allowed transitions and values.
6. Timestamps use Hibernate creation/update timestamp annotations. The SQL triggers remain in place as the database-level protection for `updated_at`.
7. `ddl-auto: validate` checks the entity mapping against the existing schema without attempting to create or mutate tables. Run the SQL schema in Supabase first.

## Connection configuration
Set these environment variables before starting the application:
- `SUPABASE_DB_URL`
- `SUPABASE_DB_USERNAME`
- `SUPABASE_DB_PASSWORD`

For example, use your Supabase project's PostgreSQL connection details and require SSL (`sslmode=require`). Never commit real credentials or expose the database password in React/React Native clients.

## Lombok
The code uses Lombok for getters, setters, and no-argument constructors. In IntelliJ IDEA, install/enable Lombok support if the IDE does not recognize generated methods.

## Repository method examples
- `productRepository.findByRestaurantIdAndIsAvailableTrue(restaurantId)`
- `restaurantOrderRepository.findByRestaurantIdAndStatusOrderByCreatedAtDesc(restaurantId, "PENDING")`
- `queueTicketRepository.findByDailyCounterIdAndStatusOrderByQueueNumberAsc(counterId, "WAITING")`
- `productModifierGroupRepository.findByIdProductId(productId)`

## Security reminder
RLS protects direct Supabase Data API access, but a Spring Boot JDBC connection is governed by the PostgreSQL role it uses. A privileged owner/postgres role may bypass RLS, so enabling RLS alone does not replace backend authorization. Do not put database credentials, a Supabase service-role key, or other privileged secrets in the frontend. Enforce authentication, restaurant membership/role authorization, and customer ownership checks in backend services. Use least-privilege database credentials for production where possible.
